# くじらのゼロ賃貸 ブログ記事 AIOリライト

ユーザーから送られてくる記事を1本ずつ、以下の手順で処理する。
**ルールの全文は `references/rules.md`**。毎回、作業を始める前に必ず全文を読み、そのとおりに作る（本文HTMLの装飾スタイル・CTAボタンHTML・固定URL・エリアリンクはすべてそこにある）。

## 手順

### 0. 準備
1. `references/rules.md` を全文読む。
2. 記事タイトルを決め、保存先フォルダ `rewrites/<記事タイトル>/` を作る（タイトル中の `/ \ : * ? " < > |` は全角に置き換えるか削る）。
3. 元記事をそのまま `rewrites/<記事タイトル>/元記事.html`（テキストなら `元記事.txt`）に保存する。URLだけ送られた場合は WebFetch で取得して保存する。
4. 複数の記事が一度に送られた場合は、1本ずつ順番に最後まで処理する。

### 1. STEP1：内容チェックと修正
- `rules.md` の「STEP1」のチェック項目1〜7をすべて確認する。
- 年によって変わる制度・数値（法改正・ガイドライン・補助金・相場・「〇年まで」等）は、WebSearch（ToolSearch で読み込む）で国土交通省・消費者庁・名古屋市など公的機関の情報を確認する。確認できなければ修正せず【要確認】へ回す。
- 確信がない箇所は直さない。根拠のない数値を作らない。

### 2. STEP2・3：リライト
- `rules.md` の STEP2・STEP3・装飾スタイル・CTAボタンHTML・導線カラーに従って書く。
- style 属性の値は「装飾スタイル」の表の値を一字一句そのまま、毎回書く。CTAボタンは見本HTMLをそのまま使う。
- 1行に1要素程度で改行してよいが、**空行・インデントは入れない**。

### 3. ファイル出力
`rewrites/<記事タイトル>/` に次の3ファイルを書く。

| ファイル | 中身 |
|---|---|
| `<記事タイトル>_本文.html` | 外枠 `<div style="…">…</div>` だけ（①） |
| `<記事タイトル>_構造化データ.html` | `<script type="application/ld+json">…</script>` だけ（②） |
| `レポート.md` | 修正レポート・【要確認】・meta description案（③と同じ内容） |

### 4. 自動チェック（必須）
次を実行し、**ERROR が0件になるまで修正→再実行**する。WARNING は内容を確認し、意図どおりなら残してよい（残した理由をレポートの【要確認】か報告に書く）。

```bash
python3 .claude/skills/kujira-aio-rewrite/scripts/check_output.py "rewrites/<記事タイトル>"
```

スクリプトが見ない点（文章の結論ファースト、FAQとスキーマの内容一致、各セクションの構成「H2→導入文→3ポイント要約→詳しく解説していきます！→H3×3」、まとめの会社紹介の項目漏れ、セクション間CTAの種類）は、`rules.md` の「出力前チェック」と合わせて目視で確認する。

### 5. 納品
1. SendUserFile で `_本文.html` と `_構造化データ.html` を送る（display: "attach"）。
2. チャットに③を書く：
   - 【修正レポート】／【要確認】（`rules.md` の書式どおり。問題なしなら「修正なし」）
   - meta description案（120文字程度、結論と名古屋市の区名を含む）
   - 「構造化データは、CMSのheadタグ・SEO用コード挿入欄に貼ってください。挿入欄がない場合、本文には貼らないでください」
   - 「本文HTMLは、CMSエディタをHTML（ソース）編集モードにしてから貼り付けてください。投稿日はいえらぶCLOUDの管理画面で設定してください」
3. `rewrites/<記事タイトル>/` をコミットし、作業ブランチに push する（コミットメッセージ例：`記事リライト: <記事タイトル>`）。
