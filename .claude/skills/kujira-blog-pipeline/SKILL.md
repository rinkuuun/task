# くじらのゼロ賃貸 ブログ自動化パイプライン

## 前提（ユーザーと決めたこと）
- 対象：いえらぶCLOUDの「ブログ」一覧の上から150記事。1記事目（名古屋市西区）は公開済み。2記事目は名古屋市中川区から。
- 既存記事に**上書き**する（元の記事は非公開で作られているだけなので、上書きして公開する）。
- 記事タイトルは、いえらぶに登録済みのタイトルを使う（ユーザーの指示がない限り変えない）。
- **公開は1日1記事。公開ボタンを押す前に必ずユーザーに確認する。**
- リライトと画像生成は先にまとめて進めてよい。ただし **Claude・Codex とも週間利用量の残りが30%を切ったら止める**（`node scripts/usage_check.js` が終了コード2）。
- 表紙画像：JPG/JPEGのみ・10MB未満（3MB以上はいえらぶ側でサイズが変わる可能性あり）。
- カテゴリ等の設定は後日ユーザーが指示する。指示がない間はカテゴリに触らない。
- ID・パスワードは扱わない。自動化専用ブラウザのプロファイルに本人がログインした状態を使う。ログインが切れていたら作業を止めて、ユーザーに `node scripts/ielove/open_browser.js` でのログインを頼む。

## 保存先
- 作業フォルダ：`%USERPROFILE%\Dropbox\不動産関係\くじら不動産\賃貸\記事作成\`（`KUJIRA_WORK_DIR` で変更可）
- 記事ごとのフォルダ：`002_<タイトル>\`（3桁番号＋タイトル。`node scripts/manifest.js add` が作る）
  - `元記事.html` / `<タイトル>_本文.html` / `<タイトル>_構造化データ.html` / `レポート.md` / 表紙画像（.jpg）
- 進捗：作業フォルダの `進捗一覧.csv`（Excelで開ける）。列：番号・タイトル・編集画面URL・フォルダ・元記事取得・リライト・画像・公開・要確認・メモ。完了した列には `済`（公開は公開日）を入れる。
  - 進捗の更新は必ず `node scripts/manifest.js set <番号> <列名> <値>` で行う。

## いえらぶ操作スクリプト（`scripts/ielove/`）
`open_browser.js` の `launch()` を使い、同じプロファイルで動かす。初期設定で次の3つを作る（画面を実際に確認してセレクタを決める）。
- `list_articles.js`：ブログ一覧を上から150件読み、番号・タイトル・編集画面URLを出力する
- `fetch_body.js <編集画面URL> <保存先>`：本文エディタをソース表示にして本文HTMLを保存する
- `fill_article.js <編集画面URL> <本文.html> <画像.jpg>`：本文をソースモードで貼り替え、表紙画像をアップロードし、「更新情報に乗せる」にチェックして、**公開ボタンは押さずに**画面のスクリーンショットを保存して止める。`--publish` を付けたときだけ公開する

## モード

### 初期設定（最初の1回）
1. `npm install` と `npx playwright install chromium` が済んでいるか確認する。
2. ユーザーに `node scripts/ielove/open_browser.js <いえらぶCLOUDのログインURL>` を実行してもらい、本人がログインしてウィンドウを閉じる。
3. ブログ一覧と編集画面を開いて画面構成を確認し、上の3スクリプトを作る。あわせて次の2点を確認してユーザーに報告する。
   - 記事ごとに head タグや SEO 用コードを入れる欄があるか（構造化データの貼り先）
   - 一覧の並び順が、公開・更新で変わるかどうか
4. `list_articles.js` の結果で、150件を `manifest.js add` に登録する。1記事目は `公開` 列を `公開済`、`リライト`・`画像` 列を `済` にする。
5. 2記事目だけで「一括リライト」→「今日の投稿」を通しで試し、ユーザーと画面を確認する。

### 一括リライト（「一括リライト」と言われたら）
`リライト` 列または `画像` 列が空の記事を、番号の小さい順に1本ずつ処理する。**1本ごとに最初に `node scripts/usage_check.js` を実行**し、終了コード2なら即停止して、ここまでの件数とリセット日時を報告する。終了コード3なら、ユーザーに `/usage` とCodexの利用状況を確認してもらう。
1. `元記事取得` が空なら `fetch_body.js` で `元記事.html` を保存し、`元記事取得` を `済` にする。
2. `kujira-aio-rewrite` スキルの手順でリライトする。出力先は記事フォルダ。`check_output.py` のERRORが0件になったら `リライト` を `済` にし、【要確認】の有無を `要確認` 列に `あり`／`なし` で書く。
3. 画像を生成する（Codexの記事連動画像生成スキル `C:\Users\rin\.codex\skills\artifact-template-kujira-article-images` に本文HTMLのファイルパスを渡す）。
   ```
   codex exec --skip-git-repo-check -C "<記事フォルダ>" "$artifact-template-kujira-article-images を使って、<本文.htmlのフルパス> の記事の表紙画像を1枚作り、このフォルダにJPGで保存してください"
   ```
   （正しい呼び出し方は初期設定で1回試して、この行を書き直す）
   できた画像を `node scripts/image_check.js <画像>` で確認し、OKなら `画像` を `済` にする。
4. 次の記事へ。止まったら、完了した件数・次に処理する番号・利用状況を報告する。

### 今日の投稿（「今日の投稿」と言われたら）
1. `公開` 列が空で `リライト`・`画像` が `済` の、番号が最も小さい記事を選ぶ。その日にすでに1本公開していたら、公開せずにそう伝える。
2. `fill_article.js` で本文・表紙画像・「更新情報に乗せる」を設定し、公開前で止める。
3. ユーザーに次を見せて確認を求める：記事番号とタイトル、スクリーンショット、`レポート.md` の【要確認】、meta description案。構造化データの貼り先があれば、その欄にも入れたかを伝える。
4. ユーザーがOKしたら `fill_article.js … --publish` で公開し、公開後のURLを開いて表示を確認する。`公開` 列に公開日を入れる。修正を頼まれたら、直して手順2からやり直す。

### 進捗（「進捗」と言われたら）
`node scripts/manifest.js show` の内容を、リライト済み・画像済み・公開済みの件数と、次に公開する記事にまとめて報告する。

## 報告の最後に
`TODO.md` に未完了の項目があれば、毎回の報告の最後に1行でリマインドする。
